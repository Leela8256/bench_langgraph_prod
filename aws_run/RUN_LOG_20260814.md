# Run log — first native x86 smoke on the AWS box (2026-08-14)

What was actually done, in order, including what broke. LangGraph arm only.
Run artifacts: `s3://rocketride-benchmark-data/leela/smoke/20260814T191343Z/`

---

## 1. How the box was driven (no SSH, no scp)

The permission set gives an interactive SSM shell and nothing else. Commands
were issued by **piping stdin into a session**:

```bash
{ sleep 3; printf '%s\n' '<command>'; sleep N; printf 'exit\n'; } \
  | aws ssm start-session --target i-0bdc8b1e18f2a5348 --region us-east-1 --profile leela
```

The `sleep 3` waits for the shell prompt; the trailing `exit` closes the
session. `Cannot perform start session: EOF` at the end is the session
closing normally, not an error.

**Long work does not run inside a session** — SSM idle-timeouts would kill it:

```bash
nohup bash -c "<command>" > ~/logs/smoke.log 2>&1 < /dev/null &
```

Then poll `tail ~/logs/smoke.log` from later one-shot sessions.

> **Gotcha, cost ~10 min.** `cmd1 && cmd2 &` backgrounds the *whole chain*, and
> the moment any part writes to the terminal the job is suspended with
> `Stopped (tty output)` — it looks launched but is frozen. Both stdout and
> stderr **and stdin** must be detached (`> log 2>&1 < /dev/null`). `disown`
> is unavailable: the SSM default shell is `sh`, not bash.

## 2. How the code got there

`git clone` of the public repo — the only inbound path, since there is no scp.
Anything uncommitted does not exist as far as the box is concerned, so the
smoke package had to be pushed first. Updates between runs: `git pull`.

## 3. How the PDFs got there — downloaded, never copied

There is no file-transfer channel, so the corpus is fetched **by the box**
([fetch_smoke_corpus.sh](box/fetch_smoke_corpus.sh)):

1. `curl` the govdocs1 archive from digitalcorpora — the same archive
   `aws/smoke.sh` already used:
   `https://digitalcorpora.s3.amazonaws.com/corpora/files/govdocs1/zipfiles/000.zip`
   (~1000 mixed-type files, cached at `~/govdocs_000.zip` so it downloads once).
2. Extract with **`python3` zipfile**, not `unzip` — the box has no `unzip` and
   no sudo to install it. Note `extractall()` drops the executable bit, which
   also bit the AWS CLI install.
3. Select the **first 10 PDFs sorted by basename** — deliberately the same rule
   gate-50 uses (`sorted(*.pdf)[:N]`), so box documents match Mac documents.
4. Record `sha256sum *.pdf > SHA256SUMS`, uploaded with the run, so any later
   run can prove it used byte-identical inputs.

Corpus selected: `000009, 000010, 000011, 000012, 000013, 000015, 000016,
000018, 000019, 000020`.

> Nine of these ten also exist in the Mac's `datasets/govdocs`; the Mac had
> `000021` where the box has `000018`, because the local corpus is a curated
> "survivors" set rather than raw archive order. **All nine shared documents
> produced byte-identical chunk hashes across native x86 and emulated ARM.**

## 4. The run itself

[smoke10.sh](box/smoke10.sh), in order:

| Step | Detail |
|---|---|
| gate | refuse unless `uname -m` is x86_64 — a wrong-arch run is not worth having |
| build | `docker compose build langgraph`, native amd64, ~5 min first time |
| record | image digest, `pip freeze` from inside the image, git SHA, dirty flag, cores/RAM/docker versions |
| boot | `docker compose up -d langgraph`, wait for `/health/ready` (warm-up gated: unhealthy until the graph has processed its own fixture once) |
| capture | `/meta` — extractor, embedding model, effective split config, reported executor width |
| **pass 1** | 10 docs, **sequential closed-loop**, with the cgroup sampler running |
| **pass 2** | the same 10 docs again, unsampled |
| report | derive metrics via `metrics/`, exit non-zero if the M0 gate is red |
| exfil | tar + `aws s3 cp` the whole evidence tree |

**Why sequential:** closed-loop yields *true service latency*. A blast run
yields batch-position latency including queue wait; the two must never be
compared (`metrics/README` M2).

**Why two passes:** M0 fails closed. `determinism()` needs a second observation
to compare chunk hashes against — one pass leaves the gate incomplete, and
incomplete is a FAIL, not a pass.

**Why the sampler covers pass 1 only:** so M7's CPU window matches M1's
throughput window. Sampling both passes would divide pass-1 documents by two
passes' CPU.

## 5. Metrics computed — and by what

Every number came from `metrics/`, never from the driver. The driver only
writes raw `per_doc.jsonl` records; `smoke_report.py` calls the canonical
modules. So the run also proves the metrics library works on the box.

| Metric | Module | Result |
|---|---|---|
| **M0** correctness gate | `m0_correctness.py` | **PASS** |
| ├ census | `census()` | 10 offered → 10 records, 0 silent, 0 duplicates, 0 unexpected failures, 0 missing vs manifest |
| ├ structure | `structure()` | every record: `identity_ok`, `sha_header_ok`, `vectors_finite` all True; ≥1 chunk; 384 dims; L2 norm within 1e-3 of 1.0; hash count == n_chunks |
| └ determinism | `determinism()` | 10 docs compared, 0 chunk-hash mismatches pass1 vs pass2 |
| **M1** throughput | `m1_m2_perf.throughput()` | **2.145 docs/s** (10 ok / 4.662 s) |
| **M2** latency | `m1_m2_perf.latency()` | p50 **0.489 s**, p95 0.948 s, max 0.948 s — closed-loop, true service latency |
| **M7** resources | `m7_resources.container_resources()` | 4.6 cpu-s, **0.54 effective cores**, peak RSS 619.2 MB, peak threads 5 |
| **M7** efficiency | `m7_resources.efficiency()` | 0.46 cpu-s/doc, 2.17 docs/cpu-s |
| M3 tokens/cost | — | N/A by definition: no LLM in this pipeline |
| M4/M5 fault | not run | needs a fault-injection run, deliberately separate |
| M6 LOC | not run | static, no run needed |

`ttfr` (time to first result) is also emitted.

### What M7 measures, and the bug it fixed

`pdf1k/proc_sampler.py` derived `cpu_total_s` from `/proc/stat`, which is **not
namespaced in Docker** and whose fields 1-7 **include `idle`** — so it reported
roughly *n_host_cpus* regardless of load. `GATE50_REPORT.json` shows the
symptom: langgraph `avg_cores: 17.81` on an 18-vCPU VM while that container was
capped at 12 CPUs, which is impossible.

[cgroup_sampler.py](box/cgroup_sampler.py) reads the container's **own cgroup**
(`cpu.stat usage_usec`, and `memory.stat anon` so page cache is not counted as
memory) and emits the same schema, so `m7_resources.py` is unchanged. Result:
0.54 effective cores — correct for a sequential run with `TORCH_THREADS=1`.

## 6. Getting results out

Uploaded from the box (`aws s3 cp --recursive`) — 13 objects including the raw
`per_doc.jsonl` for both passes and the sampler stream, not just the report,
because every metric is re-derivable from raw records forever and a report
alone cannot be recomputed or re-gated.

The AWS CLI is **not present on this Ubuntu AMI** (Amazon Linux ships it;
Canonical's images do not) and there is no sudo, so it was installed into
`~/.local` via the official installer —
[install_awscli.sh](box/install_awscli.sh).

**Verified round trip:** the run was downloaded to the Mac and the metrics
re-derived locally from the downloaded records — reproducing the box's numbers
exactly. That is checklist 4.2: proof the exfil was complete, not merely that
files exist.

```bash
aws s3 cp s3://rocketride-benchmark-data/leela/smoke/<stamp>/ ./run --recursive --profile leela
python3 aws_run/box/smoke_report.py ./run/pass1 ./run/pass2
```

## 7. What these numbers are NOT

- **Not publishable throughput.** `warm_n=0`: 10 documents cannot support the
  20/25-completion warm-start rule, so cold-cache effects are inside the window.
- **Not a comparison.** Only the LangGraph arm ran; the RocketRide arm needs the
  engine image via registry pull.
- **Not the matched-extractor configuration.** `EXTRACTOR=pypdf`, not the Tika
  mode that makes the arms byte-comparable.
- **Not a variance estimate.** Two runs (2.088 and 2.145 docs/s, ~3% apart) are
  reassuring, not a distribution.
- **Resource envelope is still Mac-tuned:** 12 CPU / 10 GB per arm, chosen for
  an 18-core Mac, unchanged on a 32-vCPU box. Must be recomputed and
  pre-registered before any measured run.
- **`/meta` misreports concurrency:** it says `executor_workers: 4`, but
  `nodes.py` uses LangGraph's default executor, width
  `min(32, os.cpu_count()+4)` — and `cpu_count()` sees host cores, not the
  cgroup quota, so the real width is 32 on this box.
